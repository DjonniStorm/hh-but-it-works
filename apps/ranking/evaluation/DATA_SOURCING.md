# Legal and realistic ML data sourcing

## Что уже используется

В репозитории лежит только маленькая обезличенная выборка профессиональных
признаков публичных вакансий «Работы России». Она получена из публичного
sample-зеркала, потому что официальный API в момент проверки закрывал
соединение. Сохраняются название роли, регион, вилка, режим, опыт и рабочие
требования. Работодатель, точный адрес, координаты и контакты не сохраняются.

- официальный каталог: https://trudvsem.ru/opendata/datasets
- документация API: https://trudvsem.ru/opendata/api
- использованный read-only sample: https://data.apicrafter.ru/tables/trud/trudvac/sample
- машинный provenance: `data/SOURCES.json`

Перед регулярной загрузкой нужно зафиксировать актуальные условия источника,
хранить дату/URL/версию выгрузки и показывать требуемую атрибуцию. Исходные
raw-выгрузки должны жить вне git в access-controlled storage.

## Рекомендуемые источники

| Что нужно                      | Источник                  | Разрешённый сценарий                                                                                                                |
| ------------------------------ | ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Вакансии РФ                    | «Работа России» open data | официальный API/выгрузка, атрибуция, удаление контактов и точных адресов                                                            |
| Профессии и skill graph ЕС     | ESCO                      | CSV/API с атрибуцией и отметкой модификаций: https://esco.ec.europa.eu/en/about-esco/escopedia/escopedia/comma-separated-values-csv |
| Occupation/skill/task graph    | O\*NET                    | база под CC BY 4.0 с атрибуцией: https://www.onetcenter.org/database.html                                                           |
| Профстандарты РФ               | Минтруд                   | официальные открытые XML/CSV: https://os.mintrud.gov.ru/opendata                                                                    |
| Реальные решения работодателей | собственный продукт       | consent/договор, purpose limitation, retention, PII separation, audit trail                                                         |

ESCO/O\*NET полезны для таксономии и hard-negative generation, но не являются
российскими outcome labels. Их нельзя выдавать за данные о найме.

## Что не делаем

- не скрейпим HH и не превращаем API-ответы HH в свободно распространяемый
  обучающий корпус без отдельного письменного разрешения;
- не коммитим реальные резюме, ФИО, телефоны, email, точные адреса, документы;
- не используем пол, возраст, национальность и другие protected attributes;
- не называем synthetic labels «человеческим gold»;
- не обучаем на кликах без debiasing позиции/экспозиции и без legal basis.

## Как получить действительно хороший gold

1. Выбрать вакансии по времени и работодателям так, чтобы holdout не делил
   сущность с train/calibration.
2. Построить обезличенный candidate pool, сохраняя только необходимые
   профессиональные признаки.
3. Дать каждую пару двум независимым экспертам. Шкала 0..3 отдельно для
   qualification, intent/opportunity и overall mutual fit.
4. Конфликты не усреднять автоматически — отправлять третьему adjudicator.
5. Загружать через `human_labels.py`; `labelConfidence` попадёт в sample weight.
6. Проверить subgroup quality, leakage, calibration/drift и только затем
   обучить с `--production-approved` и прогнать независимый held-out gate.

Synthetic generator остаётся полезным для редких/контрастных сценариев, но его
строки должны иметь меньший confidence и не могут сами открыть production lock.
