# Дорожная карта

Без дат. Три итерации после текущего MVP: сначала новые возможности в том же контуре, затем нарезка сервера, затем нарезка кабинета. Порядок такой, потому что резать UI при одном Nest рано; это же написано в [интерфейсе](/stack/web) и в [backend](/stack/backend).

Сейчас сознательно нет доски вакансий, своего отклика кандидата и коротких заданий сверх теста. Рынок это приглашение из подборки. Эти вещи вернутся, когда доска понадобится продукту, не в трёх итерациях ниже.

В ранжировании serving-бандл llm-approved (`ltr-v1.5.0-llm`). Дальше по качеству: двойная human-разметка, петля dismiss и invite в формуле. GitHub Actions на аккаунте выключен; образ в GHCR с тегом `:dev` может отставать от репозитория.

## Итерация 1. Кабинет и вспомогательный LLM

Перевод интерфейса (i18n). Сейчас кабинет и подписи причин на русском (`shared/lib/labels.ts`). Нужны словари, переключение языка, те же коды ranking без зашитого текста в UI.

Отдельное API к языковой модели: черновики заданий теста, разбор потребности, подсказки кандидату по уже посчитанным фактам. В `POST /rank` модели нет и не появится: подборка должна жить, если ключ LLM выключен. Так же записано в политике ranking.

## Итерация 2. Сервер по доменам

Nest уже модульный монолит: `users`, `auth`, `profiles`, `assessments`, `employers`. Итерация выносит модуль за сеть и меняет вызов на HTTP, без новой нарезки предметной области. Ранжирование и мок ФСП уже отдельные процессы.

## Итерация 3. Кабинет по доменам

Границы `pages/profile`, `pages/employer` и `shared` превращаются в свои бандлы (Module Federation). Кандидат и работодатель перестают ехать одним деплоем. Делается после итерации 2, чтобы фронт не опережал разрезание API.
