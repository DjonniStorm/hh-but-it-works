# Пользовательский интерфейс

При выборе решения для интерфейса рассматривались следующие подходы:

1. SPA (Single page application) - единый монолитный фронтенд
   Данный подход удобен тем, что позволяет быстро добиться желаемого результат. При негативных последствиях для SEO (которые мы постарались невелировать используя библиотеку @unhead), мы получаем быстрый результат и огромное множество решений от сообщества.
   В случае SPA мы точно сможем масштабировать наше решение. Достаточно добавлять новые компоненты и переиспользуемые схемы в контракты и начать работу.
2. Microfrontends
   Здесь мы уже можем разбить наши приложения на различные домены и использовать Module Federation (подходы iframe, webcomponents etc. не рассматривались) для их объединения.
   Но это решение имеет значительные недостатки для MVP приложения.
   - Увеличение сложности разработки при сжатых сроках
   - Бессмысленность деления frontend-а с монолитным backend-ом

В текущем решение frontend-часть приложения представляет собой SPA, которая использует React для построения пользовательского интерфейса и собирается Vite. Мы не стали изобретать "фреймворк над React" - основной стек очень прост:

- MobX для управления состоянием
- Mantine, как UI библиотека
- Zod - обший валидатор схем для всего проекта
- Nuqs - разбор и состояние в URL
- TypeScript - для выразительного и типизированного кода

Для сохранения связанности API контрактов на клиенте и на стороне сервера мы используем генератор API клиента по OpenAPI спецификации.
